# Deployment

## APB Guard demo (Render)

`render.yaml` defines the service. Render deploys automatically when `main` changes.

| Setting | Value |
|---|---|
| Build | `pip install -r requirements.txt` |
| Start | `uvicorn apb.web:app --host 0.0.0.0 --port $PORT` |
| Health check | `/healthz` |
| `PUBLIC_DEMO` | `true`: shows the public banner; the PayPal adapter is simulated |
| `ALLOW_EXECUTE` | `false` |
| `AI_BACKEND` | `none` |
| `APB_WALLET_KEY` | Generated by Render; keeps v0.1 wallet references stable |

Never add PayPal or Anthropic credentials to the public service. Verify after deploy: `/healthz` returns `{"status":"ok"}`; `/api/v3/versions` shows `payments-2026.11.1`; `/decision-lab?episode=E-AUTH-004` shows STOP.

**Rollback:** in the Render dashboard, redeploy the previous successful deploy, or revert the merge commit on `main`.

## Local sandbox execution

Copy `.env.example` to `.env`, add PayPal **sandbox** credentials and a sandbox receiver, then:

```powershell
$env:ALLOW_EXECUTE="true"; python -m apb.web
```

`PUBLIC_DEMO=true` overrides `ALLOW_EXECUTE`; the public demo can never execute.

## paymentsbenchmark.com

The site is static. The video is not in git: put `APBv2.web.mp4` in `paymentsbenchmark/media/` (create it from the master with `ffmpeg -i APBv2.mp4 -map 0 -c copy -movflags +faststart APBv2.web.mp4`).

```powershell
python paymentsbenchmark/build.py
powershell -File paymentsbenchmark/deploy/deploy.ps1
```

`deploy.ps1` uploads `dist/` as a new release under `/var/www/paymentsbenchmark/releases/`, swaps the `current` symlink, checks `nginx -t` and the site, and rolls back automatically on failure. The newest five releases are kept.

**Rollback:** on the server, point `/var/www/paymentsbenchmark/current` at the previous release directory and reload Nginx.

The pilot-request form has no backend: it opens the visitor's mail client addressed to `evaluations@paymentsbenchmark.com`. That domain needs a working mailbox (for example Cloudflare Email Routing) before the form is promoted.
